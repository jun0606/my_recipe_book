# 🔄 Cline 워크플로우 가이드라인

## 📋 표준 작업 프로세스

### 단계별 워크플로우

```
1. 📝 문제 제시 및 요구사항 파악
   └── 사용자가 구체적인 문제나 요구사항 제시
   └── 관련 로그, 에러 메시지, 예상 결과 공유

2. 🔍 초기 분석
   └── 문제의 근본 원인 파악
   └── 영향 범위 및 관련 컴포넌트 식별
   └── 현재 시스템 상태 분석

3. 💬 대화 및 уточнение (명확화)
   └── 분석 결과 공유
   └── 사용자 피드백 수렴
   └── 추가 정보 요청/제공

4. 🎯 해결 방안 도출
   └── 2-3개의 구체적인 해결 방안 제시
   └── 각 방안의 장단점 분석
   └── 추천 방안 선정

5. 💬 해결 방안 검토
   └── 제시된 방안에 대한 사용자 의견 수렴
   └── 우선순위 조정
   └── 범위 재설정

6. 📊 상세 분석 및 계획 수립
   └── 영향도 분석 (파일, 기능, 사용자 영향)
   └── 작업 분할 및 우선순위 설정
   └── 위험 요소 식별 및 완화 방안

7. 💬 계획 검토
   └── 작업 계획에 대한 사용자 승인 요청
   └── 일정 및 마일스톤 확인
   └── 의존성 및 제약사항 검토

8. 💾 관련 파일 백업
   └── 수정 대상 파일들의 백업 생성
   └── 백업 위치 및 복원 절차 문서화
   └── 백업 검증

9. 📋 수정 진행 전 브리핑
   └── 구체적인 변경사항 설명
   └── 예상 결과 및 테스트 계획
   └── 롤백 계획 및 위험 완화 전략

10. ✅ 사용자 승인
    └── 수정 진행 최종 승인 요청
    └── 승인 시점 및 유효 기간 설정

11. ⚙️ 코드 수정 실행
    └── 승인 후 실제 코드 수정 진행
    └── 단계별 검증 및 테스트
    └── 사용자 피드백 수렴
```

## 🎯 품질 관리 원칙

### 안전성 우선
- **백업 필수**: 모든 변경사항은 백업 후 진행
- **점진적 접근**: 큰 변경은 작은 단계로 분할
- **롤백 준비**: 언제든 이전 상태로 복원 가능

### 투명성 보장
- **명확한 설명**: 변경사항을 사전에 충분히 설명
- **진행 상황 공유**: 각 단계 완료 시 상태 보고
- **문제 즉시 보고**: 예상치 못한 이슈 발생 시 즉시 공유

### 사용자 중심
- **사용자 주도**: 모든 주요 결정은 사용자 승인 후 진행
- **피드백 반영**: 사용자 의견을 적극적으로 수용
- **목표 일치**: 사용자 기대치에 부합하는 결과물 제공

## 📁 프로젝트 구조 및 규칙

### 파일 조직
```
docs/
├── workflow_guidelines.md      # 이 파일 (워크플로우 가이드라인)
├── backup_guidelines.md        # 백업 가이드라인
└── change_log.md              # 변경 이력

backup_temp/
├── YYYY-MM-DD_HH-mm-ss/       # 날짜별 백업
│   ├── modified_files/        # 수정된 파일들
│   ├── backup_manifest.json   # 백업 정보
│   └── recovery_guide.md      # 복원 가이드
└── latest/                    # 최신 백업 링크
```

### 명명 규칙
- **백업 폴더**: `YYYY-MM-DD_HH-mm-ss_description`
- **임시 파일**: `temp_*.dart`, `backup_*.dart`
- **로그 파일**: `operation_YYYY-MM-DD.log`

## 🚨 위험 관리

### 고위험 작업 식별
- 데이터베이스 스키마 변경
- API 엔드포인트 수정
- 사용자 인증/권한 시스템 변경
- 대용량 데이터 처리 로직 변경

### 위험 완화 전략
1. **완전 백업**: 작업 시작 전 전체 백업
2. **단계적 배포**: 기능 단위로 점진적 적용
3. **모니터링 강화**: 변경 후 사용자 피드백 모니터링
4. **롤백 계획**: 언제든 이전 버전으로 복원 가능

## 📊 진행 상황 추적

### 상태 표시
- ✅ **완료**: 작업이 성공적으로 완료됨
- ⏳ **진행중**: 현재 작업 진행 중
- 🔄 **검토중**: 사용자 검토 대기 중
- 🚫 **중단**: 문제가 발생하여 중단됨

### 체크포인트
- 각 단계 완료 시 사용자에게 진행 상황 보고
- 예상 일정 vs 실제 일정 모니터링
- 품질 게이트: 각 단계별 필수 검증 항목

## 🔄 피드백 루프

### 지속적 개선
- 각 작업 완료 후 워크플로우 개선점 식별
- 사용자 만족도 조사 및 반영
- 프로세스 효율성 분석 및 최적화

### 커뮤니케이션
- **실시간 공유**: 중요 변경사항 즉시 공유
- **정기 보고**: 일일/주간 진행 상황 보고
- **문제 해결**: 이슈 발생 시 즉각적인 해결 방안 제시

## 📝 사용법

1. **새 작업 시작**: 이 가이드라인을 참고하여 단계별로 진행
2. **문제 발생**: 즉시 사용자에게 보고하고 함께 해결 방안 모색
3. **완료 보고**: 각 단계 완료 시 명확한 결과물 제시

**중요**: 모든 작업은 사용자의 명시적 승인 후에만 진행됩니다.
