# 베이킹 계산기 개선 요구사항

## 소개

현재 앱의 베이킹 모드 계산기는 여러 가지 계산 기능을 제공하지만, 일부 기능이 의도대로 작동하지 않고 있습니다. 또한 계산 로직이 물리적/논리적 한계를 벗어나는 경우가 있어 사용자 경험을 저하시키고 있습니다. 이 문서는 베이킹 계산기의 개선 요구사항을 정의합니다.

## 요구사항

### 요구사항 1

**사용자 스토리:** 베이킹 레시피 사용자로서, 나는 베이킹 모드와 일반 레시피 계산 로직이 분리되어 있기를 원한다. 그래서 각 모드에 특화된 계산 기능을 사용할 수 있다.

#### 인수 기준
1. WHEN 앱이 베이킹 모드를 감지하면 THEN 시스템은 베이킹 전용 계산 로직을 사용해야 한다.
2. WHEN 앱이 일반 레시피 모드를 감지하면 THEN 시스템은 일반 레시피 계산 로직을 사용해야 한다.
3. WHEN 베이킹 계산 로직이 업데이트되면 THEN 일반 레시피 계산 로직에 영향을 주지 않아야 한다.

### 요구사항 2

**사용자 스토리:** 베이킹 레시피 사용자로서, 나는 다양한 계산 모드를 사용하여 레시피를 조정하고 싶다. 그래서 내 필요에 맞게 레시피를 유연하게 조정할 수 있다.

#### 인수 기준
1. WHEN 사용자가 배율 조정 모드를 선택하면 THEN 시스템은 원본 레시피 기준으로 배율을 조정하고 원본 재료와 새로 계산된 재료를 비교 표시해야 한다.
2. WHEN 사용자가 분할 수량 기준 모드를 선택하면 THEN 시스템은 분할 수량을 입력받아 재료 총량, 분할 개수, 각 분할 무게, 남은 재료 무게를 계산해야 한다.
3. WHEN 사용자가 분할 무게 기준 모드를 선택하면 THEN 시스템은 분할 무게를 입력받아 재료 총량, 분할 개수, 각 분할 무게, 남은 재료 무게를 계산해야 한다.
4. WHEN 사용자가 배율 조정 후 분할 모드를 선택하면 THEN 시스템은 배율 조정된 레시피에 분할량/분할 수를 적용하고 원본 재료와 새로 계산된 재료를 비교 표시해야 한다.
5. WHEN 사용자가 동적 비교 모드를 선택하면 THEN 시스템은 입력값에 따라 원본 대비 증감을 자동 계산하고, 원본보다 적은 경우 비율에 맞게 모든 재료를 감소시키고, 원본보다 많은 경우 증가분을 별도 표시해야 한다.
6. WHEN 사용자가 최적 분할 모드를 선택하면 THEN 시스템은 재료가 남지 않도록 최적 분할을 계산해야 한다.

### 요구사항 3

**사용자 스토리:** 베이킹 레시피 사용자로서, 나는 입력값에 대한 강력한 유효성 검사를 원한다. 그래서 계산 오류를 방지하고 정확한 결과를 얻을 수 있다.

#### 인수 기준
1. WHEN 사용자가 배율에 0 이하의 값을 입력하면 THEN 시스템은 최소값(0.1)으로 조정하고 경고 메시지를 표시해야 한다.
2. WHEN 사용자가 배율에 비현실적으로 큰 값(10.0 초과)을 입력하면 THEN 시스템은 최대값(10.0)으로 조정하고 경고 메시지를 표시해야 한다.
3. WHEN 사용자가 분할 수량에 0 이하의 값을 입력하면 THEN 시스템은 최소값(1)으로 조정하고 경고 메시지를 표시해야 한다.
4. WHEN 사용자가 분할 수량에 비현실적으로 큰 값(100 초과)을 입력하면 THEN 시스템은 최대값(100)으로 조정하고 경고 메시지를 표시해야 한다.
5. WHEN 사용자가 분할 무게에 0 이하의 값을 입력하면 THEN 시스템은 최소값(10g)으로 조정하고 경고 메시지를 표시해야 한다.
6. WHEN 사용자가 분할 무게에 총 재료 무게를 초과하는 값을 입력하면 THEN 시스템은 최대값(총 재료 무게)으로 조정하고 경고 메시지를 표시해야 한다.
7. WHEN 사용자가 큰 숫자를 입력하면 THEN 시스템은 적절한 단위 변환을 제안해야 한다(예: 1000g → 1kg).

### 요구사항 4

**사용자 스토리:** 베이킹 레시피 사용자로서, 나는 직관적이고 사용하기 쉬운 UI를 원한다. 그래서 계산기를 효율적으로 사용할 수 있다.

#### 인수 기준
1. WHEN 사용자가 계산기 화면을 열면 THEN 시스템은 6가지 계산 모드를 탭/세그먼트로 구분하여 표시해야 한다.
2. WHEN 사용자가 모드를 선택하면 THEN 시스템은 해당 모드에 맞는 입력 컨트롤을 표시해야 한다.
3. WHEN 사용자가 입력 필드에 값을 입력하면 THEN 시스템은 슬라이더와 직접 입력을 동기화해야 한다.
4. WHEN 계산 결과가 나오면 THEN 시스템은 원본과 계산 결과를 카드 형태로 비교 표시해야 한다.
5. WHEN 계산 결과에 증감이 있으면 THEN 시스템은 화살표와 색상으로 증감을 시각화해야 한다.
6. WHEN 사용자가 입력 필드에 포커스를 두면 THEN 시스템은 해당 필드에 대한 힌트나 도움말을 표시해야 한다.

### 요구사항 5

**사용자 스토리:** 베이킹 레시피 사용자로서, 나는 계산 결과를 명확하게 이해하고 싶다. 그래서 내 레시피 조정이 어떤 영향을 미치는지 알 수 있다.

#### 인수 기준
1. WHEN 계산 결과가 표시되면 THEN 시스템은 원본 값과 계산된 값을 나란히 표시해야 한다.
2. WHEN 계산 결과에 변화가 있으면 THEN 시스템은 변화량과 변화율(%)을 표시해야 한다.
3. WHEN 최적 분할이 적용되면 THEN 시스템은 최적화 적용 여부를 명확히 표시해야 한다.
4. WHEN 사용자가 계산 결과를 확인하면 THEN 시스템은 각 재료별 원본 양과 계산된 양을 비교 표시해야 한다.
