# 고도화된 수쉐프 시스템 요구사항 문서

## 소개

이 문서는 종합 제빵 과학 통합 계산식을 기반으로 한 고도화된 수쉐프 시스템의 요구사항을 정의합니다. 기존의 단순한 수쉐프 모드를 과학적이고 정밀한 제과제빵 지원 시스템으로 완전히 재설계하여, 빵, 케이크, 쿠키, 디저트의 전 공정을 최적화하는 것을 목표로 합니다.

## 요구사항

### 요구사항 1: 종합 제빵 과학 통합 계산식 시스템

**사용자 스토리:** 제과제빵사로서, 과학적으로 검증된 계산식을 통해 정밀한 레시피 최적화를 받고 싶습니다. 그래야 일관된 품질의 제품을 만들 수 있습니다.

#### 승인 기준

1. WHEN 사용자가 레시피를 입력하면 THEN 시스템은 기본 재료 비율 최적화 공식을 적용해야 합니다
   - 하이드레이션(%) = (물의 양 ÷ 밀가루 양) × 100
   - 소금(%) = (소금 양 ÷ 밀가루 양) × 100 (표준: 1.8~2.2%)
   - 이스트(%) = (이스트 양 ÷ 밀가루 양) × 100

2. WHEN 재료 정보가 입력되면 THEN 시스템은 반죽 물리화학적 상태 조정 공식을 계산해야 합니다
   - 글루텐 강도 지수 = (유효 밀가루 단백질% × 1.2) + (소금% × 0.7) - (지방% × 0.5) - (설탕% × 0.3)

3. WHEN 환경 정보가 제공되면 THEN 시스템은 환경 및 지역 변수 보정 공식을 적용해야 합니다
   - 발효 속도 온도 보정: 2^((실제 온도 - 25) / 10)
   - 습도 보정: 1 + ((실제 습도% - 65%) × 0.005)
   - 고도 보정: 1 + ((현재 고도(m) / 1000) × 0.02)

### 요구사항 2: 공통 분석 파이프라인

**사용자 스토리:** 사용자로서, 레시피 입력부터 최종 결과까지 일관된 분석 과정을 거쳐 최적화된 가이드를 받고 싶습니다.

#### 승인 기준

1. WHEN 레시피가 입력되면 THEN 시스템은 키워드를 추출하고 적절한 모듈을 자동 선택해야 합니다

2. WHEN 환경 정보가 입력되면 THEN 시스템은 실시간으로 보정 계수를 적용해야 합니다

3. WHEN 재료 분석이 완료되면 THEN 시스템은 재료별 특성 메타데이터를 생성해야 합니다

4. WHEN 공정 분석이 시작되면 THEN 시스템은 믹싱, 발효, 굽기 단계별 최적 조건을 산출해야 합니다

### 요구사항 3: 모듈별 특화 계산 시스템

**사용자 스토리:** 제과제빵사로서, 빵, 케이크, 쿠키, 디저트 각각의 특성에 맞는 전문적인 계산과 가이드를 받고 싶습니다.

#### 승인 기준

1. WHEN 빵 레시피가 선택되면 THEN 시스템은 빵 모듈의 특화 계산식을 적용해야 합니다
   - 도법 판정 (스트레이트, 르방, 사워도우)
   - 최적 발효 시간 = 기본 발효 시간 × 미생물 활성 계수 × 반죽 물리화학 계수 × 환경 기후 계수 × 반죽 유형 보정 계수

2. WHEN 케이크 레시피가 선택되면 THEN 시스템은 케이크 모듈의 특화 계산식을 적용해야 합니다
   - 내부 촉감 지수 = (최종 내부 온도) × (하이드레이션) × (글루텐 탄성 지수) - (총 수분 손실%)

3. WHEN 쿠키 레시피가 선택되면 THEN 시스템은 쿠키 모듈의 특화 계산식을 적용해야 합니다
   - 스프레드 예측 지수 = (지방% × 0.8) + (당% × 0.5) - (수분% × 0.3)

4. WHEN 디저트 레시피가 선택되면 THEN 시스템은 디저트 모듈의 특화 계산식을 적용해야 합니다
   - 푸딩: 응고 온도 곡선 = 젤라틴/펙틴 농도 × (온도 - 기준 온도) × pH 보정
   - 아이스크림: 오버런 계산 = ((완제품 부피 - 원액 부피) ÷ 원액 부피) × 100

### 요구사항 4: 실시간 알람 시스템

**사용자 스토리:** 제과제빵사로서, 발효나 굽기 과정에서 최적 조건을 벗어날 때 즉시 알림을 받고 싶습니다. 그래야 적시에 조치를 취할 수 있습니다.

#### 승인 기준

1. WHEN 발효 시간이 예측값에서 ±10% 이상 벗어나면 THEN 시스템은 푸시 알림을 전송해야 합니다

2. WHEN 굽기 온도가 목표값에서 ±5% 이상 벗어나면 THEN 시스템은 즉시 알람을 발생시켜야 합니다

3. WHEN 환경 변수(온도, 습도)가 허용 범위를 벗어나면 THEN 시스템은 조치 가이드와 함께 알림을 보내야 합니다

4. WHEN 알람이 발생하면 THEN 시스템은 구체적인 조치 방법을 제시해야 합니다

### 요구사항 5: 시각화 대시보드

**사용자 스토리:** 사용자로서, 제과제빵 과정의 주요 지표들을 실시간으로 시각적으로 확인하고 싶습니다.

#### 승인 기준

1. WHEN 발효가 진행되면 THEN 시스템은 볼륨 지수를 실시간 그래프로 표시해야 합니다

2. WHEN 굽기가 진행되면 THEN 시스템은 크러스트 색상 지수를 색상 코드로 시각화해야 합니다

3. WHEN 공정이 진행되면 THEN 시스템은 내부 기공 점수를 히스토그램으로 표시해야 합니다

4. WHEN 환경 변수가 변화하면 THEN 시스템은 온도, 습도, 기압을 실시간으로 모니터링해야 합니다

### 요구사항 6: 각국 전통 디저트 데이터베이스

**사용자 스토리:** 제과제빵사로서, 세계 각국의 전통 디저트를 과학적으로 정확하게 재현하고 싶습니다.

#### 승인 기준

1. WHEN 프랑스 크렘 브륄레가 선택되면 THEN 시스템은 응고 온도와 카라멜화 지수 계산식을 적용해야 합니다
   - 응고 온도 = (단백질% × 0.8) + (온도 - 80) × 0.5
   - 카라멜화 지수 = (설탕% × 0.6) + (굽기 온도 × 0.4) - (습도 × 0.2)

2. WHEN 이탈리아 젤라토가 선택되면 THEN 시스템은 오버런과 결정 크기 계산식을 적용해야 합니다
   - 오버런 = ((완제품 부피 - 원액 부피) ÷ 원액 부피) × 100
   - 결정 크기 = (냉동 속도 × 0.7) + (지방% × 0.3)

3. WHEN 일본 와가시가 선택되면 THEN 시스템은 젤화 곡선과 수분 보유율 계산식을 적용해야 합니다
   - 젤화 곡선 = (한천 농도 × 0.8) + (온도 - 85) × 0.2
   - 수분 보유율 = 초기 수분율 - (가열 시간 × 0.05)

4. WHEN 미국 마시멜로가 선택되면 THEN 시스템은 젤화 강도와 기포 구조 지수를 계산해야 합니다
   - 젤화 강도 = (젤라틴 농도 × 0.9) + (수분% × 0.1)
   - 기포 구조 지수 = (휘핑 시간 × 0.6) + (당도% × 0.4)

5. WHEN 스페인 츄로스가 선택되면 THEN 시스템은 크러스트 바삭함과 수분 손실율을 계산해야 합니다
   - 크러스트 바삭함 지수 = (튀김 온도 × 0.7) + (기름 흡수율 × 0.3)
   - 수분 손실율 = (튀김 시간 × 0.2) + (반죽 수분% × 0.1)

### 요구사항 7: 환경 변수 보정 시스템

**사용자 스토리:** 제과제빵사로서, 작업실의 환경 조건(온도, 습도, 고도, 계절)을 수동으로 입력하여 환경에 맞는 보정된 레시피를 받고 싶습니다. 작업실마다 환경이 다르므로 정확한 측정값을 직접 입력하는 것이 가장 정확합니다.

#### 승인 기준

1. WHEN 사용자가 작업실 온도를 수동 입력하면 THEN 시스템은 온도 보정 계수를 자동 적용해야 합니다
   - 온도 보정 = 1 + ((실제 온도 - 25) / 10)

2. WHEN 사용자가 작업실 습도를 수동 입력하면 THEN 시스템은 습도 보정 계수를 자동 적용해야 합니다
   - 습도 보정 = 1 + ((실제 습도% - 65) × 0.005)

3. WHEN 사용자가 작업실 고도를 수동 입력하면 THEN 시스템은 기압 보정을 적용해야 합니다
   - 고도 보정 = 1 + ((현재 고도(m) / 1000) × 0.02)

4. WHEN 사용자가 계절 정보를 선택하면 THEN 시스템은 계절별 특성을 반영해야 합니다

5. WHEN 향후 호환 가능한 온도계/습도계/고도계가 출시되면 THEN 시스템은 해당 기기와의 연동을 지원할 수 있어야 합니다

### 요구사항 8: 품질 평가 및 피드백 시스템

**사용자 스토리:** 제과제빵사로서, 완성된 제품의 품질을 객관적으로 평가받고 다음 제작에 반영할 수 있는 피드백을 받고 싶습니다.

#### 승인 기준

1. WHEN 제품이 완성되면 THEN 시스템은 볼륨 지수를 계산해야 합니다
   - 볼륨 지수 = 빵 부피 / 오븐 투입 전 반죽 부피

2. WHEN 크러스트가 형성되면 THEN 시스템은 크러스트 색상 지수를 평가해야 합니다

3. WHEN 내부 구조가 분석되면 THEN 시스템은 기공 구조 점수를 산출해야 합니다

4. WHEN 품질 평가가 완료되면 THEN 시스템은 예측값과 실제값을 비교하여 피드백을 제공해야 합니다

### 요구사항 9: 온디바이스 전용 시스템

**사용자 스토리:** 사용자로서, 외부 API나 클라우드 없이 완전히 온디바이스에서 동작하는 안전하고 독립적인 제과제빵 시스템을 사용하고 싶습니다.

#### 승인 기준

1. WHEN 앱이 실행되면 THEN 시스템은 인터넷 연결 없이도 모든 기능이 동작해야 합니다

2. WHEN 계산이 수행되면 THEN 모든 처리는 디바이스 내부에서만 이루어져야 합니다

3. WHEN 데이터가 저장되면 THEN 모든 데이터는 로컬 디바이스에만 저장되어야 합니다

4. WHEN 향후 AI 기능이 추가되면 THEN 온디바이스 AI 모델을 사용해야 합니다

5. WHEN 특정 업체의 의뢰가 있거나 표준화된 IoT 센서가 제품화되면 THEN 센서 연동 기능을 검토할 수 있어야 합니다

### 요구사항 10: 데이터 구조 및 저장

**사용자 스토리:** 개발자로서, 복잡한 계산 결과와 메타데이터를 효율적으로 저장하고 관리하고 싶습니다.

#### 승인 기준

1. WHEN 레시피 데이터가 생성되면 THEN 시스템은 구조화된 JSON 형태로 저장해야 합니다

2. WHEN 계산 결과가 생성되면 THEN 시스템은 재료메타, 공정메타, 품질메타를 포함해야 합니다

3. WHEN 디저트 데이터가 요청되면 THEN 시스템은 각국 전통 디저트 데이터베이스에서 정확한 정보를 제공해야 합니다

4. WHEN 사용자 설정이 변경되면 THEN 시스템은 개인화된 설정을 유지해야 합니다
