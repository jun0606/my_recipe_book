# 실용적 레시피 계산기 요구사항 문서 v2.0

## 소개

일반 사용자부터 전문 베이커리까지 실제 현장에서 필요한 실용적인 레시피 계산 기능을 제공하는 시스템입니다. 완전한 오프라인 우선 설계와 유연한 기능 커스터마이징을 통해 모든 사용자의 니즈를 충족합니다.

## 핵심 설계 원칙

### 🔒 **완전 오프라인 우선 + 선택적 AI 기능**
- 모든 기본 기능은 인터넷 연결 없이 작동
- AI 기능은 선택사항으로 제공 (로컬 AI 또는 온라인 AI)
- 사용자가 AI 기능 사용 여부를 자유롭게 선택

### 🎛️ **유연한 기능 커스터마이징**
- 고정된 "초보자/전문가" 모드 대신 개별 기능별 활성화/비활성화
- 사용자가 필요한 기능만 선택해서 인터페이스 구성
- 호기심 많은 일반인도 전문 기능을 체험해볼 수 있는 "도킹" 시스템

### ⚖️ **상업적 사용 완전 무료 라이브러리만 사용**
- MIT, Apache 2.0, BSD 등 상업적 사용 허용 라이선스만 사용
- GPL, LGPL 등 카피레프트 라이선스 완전 배제
- 모든 의존성 라이브러리 라이선스 사전 검증

## 요구사항

### 요구사항 1: 완전 오프라인 기본 기능

**사용자 스토리:** 모든 사용자로서, 인터넷 연결 없이도 모든 핵심 레시피 계산 기능을 사용하고 싶다.

#### 수용 기준
1. WHEN 사용자가 인터넷 연결이 없는 환경에서 앱을 사용하면 THEN 모든 기본 계산 기능이 정상 작동한다
2. WHEN 사용자가 분할 계산, 재료 조정, 버전 관리를 사용하면 THEN 네트워크 연결 없이도 즉시 처리된다
3. WHEN 사용자가 레시피 데이터를 저장하거나 불러오면 THEN 모든 데이터가 로컬에 저장되고 접근된다
4. IF 네트워크 연결이 끊어져도 THEN 진행 중인 작업이 중단되지 않고 계속 진행된다

### 요구사항 2: 선택적 AI 기능 (장기 계획)

**사용자 스토리:** 고급 사용자로서, 원한다면 AI 기능을 활용해서 더 스마트한 레시피 분석과 제안을 받고 싶다.

#### 수용 기준
1. WHEN 사용자가 AI 기능을 활성화하면 THEN 로컬 AI 또는 온라인 AI 중 선택할 수 있다
2. WHEN 로컬 AI를 선택하면 THEN 기기 내에서 AI 추론이 실행되고 인터넷이 필요하지 않다
3. WHEN 온라인 AI를 선택하면 THEN 인터넷 연결 시에만 AI 기능이 작동하고 오프라인에서는 기본 기능으로 대체된다
4. WHEN AI 기능을 비활성화하면 THEN 모든 AI 관련 UI가 숨겨지고 기본 기능만 표시된다

### 요구사항 3: 유연한 기능 커스터마이징 시스템

**사용자 스토리:** 모든 수준의 사용자로서, 내가 필요한 기능만 선택해서 나만의 인터페이스를 구성하고 싶다.

#### 수용 기준
1. WHEN 사용자가 설정에서 기능을 선택하면 THEN 개별 기능별로 활성화/비활성화할 수 있다
2. WHEN 일반 사용자가 호기심으로 전문 기능을 써보고 싶으면 THEN "체험 모드"로 임시 활성화할 수 있다
3. WHEN 사용자가 자주 쓰는 기능 조합이 있으면 THEN 프리셋으로 저장하고 빠르게 전환할 수 있다
4. WHEN 사용자가 기능을 처음 사용하면 THEN 간단한 가이드와 함께 안전하게 체험할 수 있다

### 요구사항 4: 배치 계산 및 생산 계획 기능

**사용자 스토리:** 베이커리 운영자로서, 여러 제품을 동시에 생산할 때 공통 재료를 통합 계산하고 효율적인 생산 계획을 세우고 싶다.

#### 수용 기준
1. WHEN 사용자가 "A빵 20개, B빵 15개, C빵 10개"를 입력하면 THEN 공통 재료를 통합해서 총 필요량을 계산한다
2. WHEN 배치 계산 결과가 나오면 THEN 재료별 구매 리스트와 작업 순서를 제안한다
3. WHEN 생산 용량 제한이 있으면 THEN 오븐 크기, 작업 시간을 고려한 최적 생산 스케줄을 제안한다
4. WHEN 재료 재고가 부족하면 THEN 대체 방안이나 생산량 조정을 제안한다

### 요구사항 5: 원가 계산 및 수익성 분석

**사용자 스토리:** 베이커리 사업자로서, 각 제품의 정확한 원가를 계산하고 적정 판매가격을 결정하고 싶다.

#### 수용 기준
1. WHEN 사용자가 재료 단가를 입력하면 THEN 레시피별 재료비를 자동 계산한다
2. WHEN 인건비, 임대료, 유틸리티 비용을 입력하면 THEN 간접비를 포함한 총 원가를 계산한다
3. WHEN 목표 마진율을 설정하면 THEN 적정 판매가격을 제안한다
4. WHEN 재료 가격이 변동하면 THEN 원가 변화를 추적하고 가격 조정 필요성을 알려준다

### 요구사항 6: 레시피 성공률 추적 및 개선 제안

**사용자 스토리:** 베이킹 학습자로서, 내가 만든 레시피들의 성공률을 추적하고 실패 패턴을 분석해서 실력을 향상시키고 싶다.

#### 수용 기준
1. WHEN 사용자가 레시피를 완성한 후 결과를 기록하면 THEN 성공/실패 여부와 문제점을 저장한다
2. WHEN 여러 번의 베이킹 기록이 쌓이면 THEN 성공률 통계와 실패 패턴을 분석해서 보여준다
3. WHEN 특정 레시피에서 자주 실패하면 THEN 가능한 원인과 개선 방안을 제안한다
4. WHEN 사용자의 실력이 향상되면 THEN 더 도전적인 레시피나 기법을 추천한다

### 요구사항 7: 조리 모드 및 음성 지원 (장기 계획)

**사용자 스토리:** 베이킹 중인 사용자로서, 손이 더러운 상황에서도 음성으로 레시피 정보를 확인하고 다음 단계로 진행하고 싶다.

#### 수용 기준
1. WHEN 사용자가 조리 모드를 활성화하면 THEN 큰 글씨와 간단한 인터페이스로 전환된다
2. WHEN 사용자가 "다음"이라고 말하면 THEN 다음 재료나 단계 정보를 음성으로 읽어준다
3. WHEN 사용자가 "재료 반복"이라고 말하면 THEN 현재 재료 정보를 다시 읽어준다
4. WHEN 다국어 지원이 활성화되면 THEN 선택한 언어로 음성 안내가 제공된다

### 요구사항 8: 상업적 사용 완전 무료 라이브러리 준수

**사용자 스토리:** 개발팀으로서, 상업적 사용에 문제가 없는 라이브러리만 사용해서 법적 리스크 없이 앱을 배포하고 싶다.

#### 수용 기준
1. WHEN 새로운 라이브러리를 추가할 때 THEN MIT, Apache 2.0, BSD 등 상업적 사용 허용 라이선스인지 확인한다
2. WHEN GPL, LGPL 등 카피레프트 라이선스를 발견하면 THEN 대체 라이브러리를 찾거나 자체 구현한다
3. WHEN 의존성 라이브러리가 업데이트되면 THEN 라이선스 변경 여부를 자동으로 체크한다
4. WHEN 앱을 배포할 때 THEN 모든 사용된 라이브러리의 라이선스 정보를 명시한다

### 요구사항 9: 기능별 도킹 및 체험 시스템

**사용자 스토리:** 호기심 많은 일반 사용자로서, 전문가 기능들을 부담 없이 체험해보고 필요하면 계속 사용하고 싶다.

#### 수용 기준
1. WHEN 일반 사용자가 전문 기능에 관심을 보이면 THEN "체험해보기" 옵션을 제공한다
2. WHEN 체험 모드를 활성화하면 THEN 해당 기능을 임시로 사용할 수 있고 가이드가 함께 제공된다
3. WHEN 체험 후 만족하면 THEN 해당 기능을 정식으로 활성화할 수 있다
4. WHEN 체험 후 불필요하다고 판단하면 THEN 쉽게 비활성화하고 원래 인터페이스로 돌아갈 수 있다

### 요구사항 10: 지능형 재료 대체 및 알레르기 대응

**사용자 스토리:** 알레르기가 있는 사용자로서, 특정 재료를 안전하게 대체할 수 있는 방법을 알고 싶다.

#### 수용 기준
1. WHEN 사용자가 알레르기 정보를 입력하면 THEN 해당 재료가 포함된 레시피에서 경고를 표시한다
2. WHEN 알레르기 재료 대체가 필요하면 THEN 안전하고 맛에 영향을 최소화하는 대체재를 제안한다
3. WHEN 대체재 사용 시 THEN 필요한 비율 조정과 예상되는 맛/질감 변화를 알려준다
4. WHEN 대체가 불가능한 경우 THEN 명확히 안내하고 다른 레시피를 추천한다

### 요구사항 11: 계절별 재료 최적화 및 로컬 푸드 지원

**사용자 스토리:** 지속가능한 베이킹을 추구하는 사용자로서, 계절에 맞는 재료를 사용하고 지역 특산물을 활용하고 싶다.

#### 수용 기준
1. WHEN 현재 계절 정보를 확인하면 THEN 제철 재료를 우선적으로 추천한다
2. WHEN 지역을 설정하면 THEN 해당 지역의 특산물을 활용한 레시피 변형을 제안한다
3. WHEN 재료의 제철이 아닐 때 THEN 대체 재료나 보관 방법을 안내한다
4. WHEN 로컬 푸드를 선택하면 THEN 푸드 마일리지와 환경 영향을 표시한다

### 요구사항 12: 협업 및 레시피 공유 시스템

**사용자 스토리:** 베이킹 커뮤니티 멤버로서, 다른 사용자들과 레시피를 공유하고 함께 개선해나가고 싶다.

#### 수용 기준
1. WHEN 사용자가 레시피를 공유하고 싶으면 THEN 개인정보를 제외한 레시피 데이터만 내보낼 수 있다
2. WHEN 다른 사용자의 레시피를 받으면 THEN 안전성을 검증한 후 가져올 수 있다
3. WHEN 공유된 레시피를 수정하면 THEN 원작자 정보를 유지하면서 파생 관계를 기록한다
4. WHEN 레시피에 대한 피드백을 주고받으면 THEN 개선 사항을 추적하고 반영할 수 있다

## 기능 우선순위

### 🚀 **1단계 (MVP - 즉시 구현)**
- 기본 분할 계산 (요구사항 1)
- 유연한 기능 커스터마이징 (요구사항 3)
- 상업적 라이선스 준수 (요구사항 8)

### 📈 **2단계 (핵심 기능 확장)**
- 배치 계산 (요구사항 4)
- 원가 계산 (요구사항 5)
- 기능 도킹 시스템 (요구사항 9)

### 🎯 **3단계 (고급 기능)**
- 성공률 추적 (요구사항 6)
- 재료 대체 시스템 (요구사항 10)
- 계절별 최적화 (요구사항 11)

### 🌟 **4단계 (장기 계획)**
- 선택적 AI 기능 (요구사항 2)
- 음성 지원 (요구사항 7)
- 협업 시스템 (요구사항 12)

- iOS, Android 네이티브 앱
- 태블릿 최적화 필수
- 오프라인 우선 아키텍처

### 🔒 **라이선스 제약**
- MIT, Apache 2.0, BSD 라이선스만 사용
- GPL, LGPL 완전 배제
- 모든 의존성 라이선스 자동 검증

- AI 없이도 모든 핵심 기능 완전 작동

- 모든 데이터 로컬 저장 (SQLite)
