# 실용적 레시피 계산기 요구사항 문서

## 소개

일반 사용자부터 전문 베이커리까지 실제 현장에서 필요한 실용적인 레시피 계산 기능을 제공하는 시스템입니다. 복잡한 베이킹 과학보다는 실무에서 자주 발생하는 상황들을 해결하는 데 중점을 둡니다.

## 요구사항

### 요구사항 1: 일반 사용자를 위한 간단한 분할 계산

**사용자 스토리:** 일반 사용자로서, 유튜브나 레시피 책에서 본 레시피를 내가 원하는 개수로 쉽게 조정하고 싶다.

#### 수용 기준
1. WHEN 사용자가 "5개 나오는 레시피를 6개로 만들고 싶다"고 입력하면 THEN 시스템은 모든 재료량을 1.2배로 계산해서 보여준다
2. WHEN 사용자가 분할 개수를 입력하면 THEN 시스템은 개별 무게와 남은 재료량을 함께 표시한다
3. WHEN 계산 결과가 나오면 THEN 사용자는 일반 계산기 없이도 바로 이해할 수 있는 형태로 표시된다
4. IF 사용자가 "설탕을 조금 더 넣어도 될까?" 같은 재료 조정을 원하면 THEN 시스템은 안전한 조정 범위를 제안한다

### 요구사항 2: 베이커리를 위한 효율적인 배수 계산

**사용자 스토리:** 베이커리 직원으로서, 기존 레시피를 빠르게 2배, 3배로 늘리거나 특정 개수로 조정해서 생산하고 싶다.

#### 수용 기준
1. WHEN 베이커리 직원이 "오늘 이 빵 20개 더 만들어야 해"라고 상황이 발생하면 THEN 시스템은 즉시 필요한 재료량을 계산해준다
2. WHEN 급하게 분할 무게만 변경해야 하는 상황이면 THEN 시스템은 다른 설정 변경 없이 분할 무게만 빠르게 조정할 수 있다
3. WHEN 남은 재료로 데코레이션용 제품을 만들어야 하면 THEN 시스템은 남은 재료량을 명확히 표시하고 활용 방안을 제안한다
4. WHEN 본사 레시피를 현장에서 사용하면 THEN 복잡한 전문 계산 없이도 정확한 결과를 얻을 수 있다

### 요구사항 3: 연구원을 위한 전문적인 레시피 개발 도구

**사용자 스토리:** 제품 개발 연구원으로서, 신제품 개발 시 필요한 다양한 계산과 분석 도구를 한 곳에서 사용하고 싶다.

#### 수용 기준
1. WHEN 연구원이 신제품을 개발할 때 THEN 시스템은 전문가용 모드와 비전문가용 모드를 구분해서 제공한다
2. WHEN 레시피를 수정하다가 원본을 잃어버릴 위험이 있으면 THEN 시스템은 자동으로 히스토리를 저장하고 복원할 수 있게 한다
3. WHEN 수정된 부분을 확인하고 싶으면 THEN 시스템은 변경된 재료나 수치를 다른 색으로 표시한다
4. WHEN 이전 버전과 비교하고 싶으면 THEN 시스템은 이전 레시피와 현재 레시피를 나란히 비교해서 보여준다

### 요구사항 4: 레시피 파생 및 계보 관리 시스템

**사용자 스토리:** 레시피 개발자로서, 기존 레시피를 바탕으로 퓨전이나 바리에이션을 만들 때 계보를 추적하고 관리하고 싶다.

#### 수용 기준
1. WHEN 기존 레시피를 바탕으로 새로운 레시피를 만들면 THEN 시스템은 자동으로 부모-자식 관계를 기록한다
2. WHEN 레시피 파생도를 확인하고 싶으면 THEN 시스템은 트리 구조로 시각화해서 보여준다
3. WHEN 특정 레시피의 계보를 탐색하고 싶으면 THEN 시스템은 어떤 레시피에서 파생되었는지, 어떤 레시피들이 파생되었는지 쉽게 볼 수 있게 한다
4. WHEN 두 개 이상의 레시피를 조합해서 새로운 레시피를 만들면 THEN 시스템은 다중 부모 관계도 기록하고 표시한다

### 요구사항 5: 모바일 최적화된 오프라인 계산 시스템

**사용자 스토리:** 모바일 기기 사용자로서, 인터넷 연결 없이도 빠르고 정확한 계산을 하고 싶다.

#### 수용 기준
1. WHEN 사용자가 모바일이나 태블릿에서 앱을 사용하면 THEN 모든 계산이 기기 내에서 즉시 처리된다
2. WHEN 인터넷 연결이 없는 환경에서도 THEN 모든 핵심 기능이 정상적으로 작동한다
3. WHEN 복잡한 AI나 머신러닝 기능이 필요하면 THEN 클라우드 없이도 기본적인 지능형 기능을 제공한다
4. WHEN 계산 결과가 나오면 THEN 모바일 화면에 최적화된 형태로 명확하게 표시된다

### 요구사항 6: 직관적인 재료 조정 및 안전성 검증

**사용자 스토리:** 베이킹 초보자로서, 레시피를 조정할 때 실패하지 않도록 안전한 범위 내에서 변경하고 싶다.

#### 수용 기준
1. WHEN 사용자가 "설탕을 더 넣고 싶다"고 하면 THEN 시스템은 안전한 증가 범위(예: +10%까지)를 제안한다
2. WHEN 위험한 조정(예: 베이킹파우더 50% 증가)을 시도하면 THEN 시스템은 경고 메시지와 함께 대안을 제시한다
3. WHEN 재료 대체가 필요하면 THEN 시스템은 1:1 대체 가능한 재료와 비율을 제안한다
4. WHEN 조정된 레시피를 사용하면 THEN 원본 레시피 대비 예상되는 맛이나 질감 변화를 미리 알려준다

### 요구사항 7: 효율적인 레시피 버전 관리

**사용자 스토리:** 레시피 관리자로서, 레시피의 변경 이력을 추적하고 필요시 이전 버전으로 되돌리고 싶다.

#### 수용 기준
1. WHEN 레시피를 수정할 때마다 THEN 시스템은 자동으로 버전을 생성하고 타임스탬프를 기록한다
2. WHEN 수정 내용을 확인하고 싶으면 THEN 시스템은 변경된 부분을 하이라이트로 표시한다
3. WHEN 이전 버전으로 되돌리고 싶으면 THEN 시스템은 원클릭으로 복원할 수 있게 한다
4. WHEN 여러 버전을 비교하고 싶으면 THEN 시스템은 나란히 비교 뷰를 제공한다

### 요구사항 8: 실용적인 남은 재료 활용 시스템

**사용자 스토리:** 베이킹 실무자로서, 분할 후 남은 재료를 효율적으로 활용할 수 있는 방법을 알고 싶다.

#### 수용 기준
1. WHEN 분할 계산 후 재료가 남으면 THEN 시스템은 남은 재료량을 정확히 표시한다
2. WHEN 남은 재료로 만들 수 있는 것을 알고 싶으면 THEN 시스템은 적합한 레시피나 용도를 제안한다
3. WHEN 데코레이션용 재료가 필요하면 THEN 시스템은 남은 재료로 만들 수 있는 데코레이션을 제안한다
4. WHEN 재료 낭비를 최소화하고 싶으면 THEN 시스템은 최적의 분할 방법을 제안한다

### 요구사항 9: 사용자 레벨별 인터페이스 적응

**사용자 스토리:** 다양한 수준의 사용자로서, 내 실력과 필요에 맞는 적절한 수준의 인터페이스를 사용하고 싶다.

#### 수용 기준
1. WHEN 초보 사용자가 앱을 사용하면 THEN 시스템은 복잡한 기능을 숨기고 핵심 기능만 보여준다
2. WHEN 전문가가 앱을 사용하면 THEN 시스템은 고급 기능과 상세한 정보를 모두 제공한다
3. WHEN 사용자 레벨을 변경하고 싶으면 THEN 시스템은 설정에서 쉽게 변경할 수 있게 한다
4. WHEN 기능을 학습하면서 레벨업하고 싶으면 THEN 시스템은 점진적으로 더 많은 기능을 제공한다

### 요구사항 10: 빠른 접근성과 즐겨찾기 시스템

**사용자 스토리:** 자주 사용하는 사용자로서, 내가 자주 쓰는 레시피와 기능에 빠르게 접근하고 싶다.

#### 수용 기준
1. WHEN 자주 사용하는 레시피가 있으면 THEN 시스템은 즐겨찾기로 등록하고 빠른 접근을 제공한다
2. WHEN 최근 사용한 레시피를 다시 쓰고 싶으면 THEN 시스템은 최근 사용 이력을 보여준다
3. WHEN 특정 계산 모드를 자주 사용하면 THEN 시스템은 해당 모드를 기본값으로 설정할 수 있게 한다
4. WHEN 앱을 열면 THEN 시스템은 사용자가 가장 자주 하는 작업을 바로 시작할 수 있게 한다
